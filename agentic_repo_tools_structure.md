# Agentic Repo Tools and Knowledge Base Structure

This document defines the **Agentic Repo Tools repository**, which can be cloned into any project to provide reusable, agentic coding, planning, and organization capabilities. It separates stable, reusable tools from dynamic, project-specific knowledge.

---

## 1. **Repository Overview**

Top-level structure:

```
agentic_repo_tools/                    # The toolkit repository itself
│
├── planning_docs/                     # Toolkit development planning (gitignored in consumer repos)
│
├── .agentic_repo_tools/              # The distributable product (cloned into projects)
│   │
│   ├── 01_project_agnostic_agentic_system/     
|   |   |  # the stable (unchanging core of the tool)
│   │   ├── procedural_docs/          # Agent instructions and workflows (chronological, process-based organization)
│   │   |   └── Stage_X
│   │   |      └── Task_X
│   │   |          ├──  Agent_Instructions.md. # Includes definition of what docs to bring into context + specification of deliverables + tools to use
│   │   |          └──  Task-Specific-Agent-Definition-Doc.md  # per claude sub-agent requirements
│   │   └── tools_src/                # Source code for deterministic and agentic tools
│   │       └── (functional decomposition with hierarchical folders)
│   │           ├── setup/
│   │           ├── planning/
│   │           ├── implementation/
│   │           ├── organization/
│   │           └── testing/
│   │
│   ├── 02_project_specific_knowledge_base/     # Storing intermeidate data & files generated by tools 
│   │   ├── setup/                    # Setup artifacts (configs, initialization logs)
│   │   ├── planning/                 # Planning deliverables (vision, MVPs, sprint logs)
│   │   ├── implementation/           # Implementation artifacts (code logs, commit metadata)
│   │   ├── testing/                  # Test outputs (results, coverage, regression data)
│   │   ├── organization/             # Organization artifacts (refactor logs, file move history)
│   │   └── (process-step organization mirroring 01/tools_src/ for intuitive navigation)
│   │
│   └── README.md                     # Describes architecture and usage
│
└── (other toolkit development files)
```

---

## 2. **Core Conceptual Separation**

| Domain                                   | Description                                                   | Contents                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **Project-Agnostic System (01)**         | Stable, reusable tools and procedures shared across projects. | Procedural docs and source code organized by functional decomposition (process phases).      |
| **Project-Specific Knowledge Base (02)** | Dynamic, evolving metadata and outputs generated per project. | Process-step organized artifacts (setup, planning, implementation, testing, organization).   |

This ensures a clear boundary between **capability** and **state** — what the agent can do vs. what the agent learns or generates.

---

## 3. **Functional Decomposition**

Functional decomposition organizes tools and logic by major development phases, scaling from atomic scripts to high-level orchestration:

1. **Setup** – initializes configurations, environments, and templates.
2. **Planning** – defines MVPs, increments of value, and sprints.
3. **Implementation** – manages coding, commits, and telemetry.
4. **Organization** – maintains documentation, structure, and refactoring.
5. **Testing** – ensures continuous validation and test-driven integrity.

Each functional area contains only deterministic scripts and supporting code within `tools_src/`. Agentic procedures are stored separately in `procedural_docs/`, organized chronologically rather than functionally, and may reference the same tool functions at multiple points in the workflow.

---

## 4. **Knowledge Base Organization**

- The knowledge base uses **process-step organization** mirroring the functional phases in `01/tools_src/`.
- Artifacts are stored in the phase that generated them (e.g., test results in `testing/`, commit logs in `implementation/`).
- This provides intuitive navigation: finding outputs matches the mental model of "what phase am I working in?"
- Tools write to predictable locations using relative paths (e.g., `../../02_project_specific_knowledge_base/implementation/logs/`).
- If database migration becomes necessary later, a migration script can reorganize data without changing the current workflow.
- Maintain separation from project source files to ensure a clean, auditable repo state.

---

## 5. **Usage and Maintenance**

1. Clone or import `.agentic_repo_tools/` from the toolkit repo into any target project repo.
2. The `planning_docs/` folder remains in the toolkit repo only - it contains toolkit development planning and should not be distributed to consumer projects.
3. The `01_project_agnostic_agentic_system` remains immutable during testing cycles within consumer projects.
4. All evolving outputs and metadata live under `02_project_specific_knowledge_base`.
5. When updating the toolkit, do so in its dedicated repo, not within individual projects.
